# Complete the independent Note GUI library

## Objective and ownership

Complete the library requirements in `docs/functional-specification.md` and
`CONTRACT.md`, qualify its package and supported browser/native behavior, and keep
its source, notices, evidence and documentation consistent. Note GUI owns its
architecture, development priorities and release acceptance as an independent
project.

Each consuming project decides how to use the library. KMS adoption, `/notes/`
routes, Jenkins routing, backend pipelines, rule approval, historical business
corpora, migrations and product milestones are consumer-owned. They are not
requirements, blockers or retirement conditions for this project. The optional
`/kms` adapter remains part of the published API with its documented behavior.

- Cover F01–F10 and G01–G11, including rich documents, independent dirty panes,

- Verify the public contract through repository-owned component tests, the real
  independent persistent host and actual built-package browser/native checks.
  Supplied host data must exercise empty/populated/denied/failed/late results.
- Qualify exports, strict declarations, CSS/chunks/local fonts, license/notices,
  upstream provenance and matching corresponding source for the exact release.
- Preserve the existing Linux and desktop/narrow scope, native-editor controls,
  revision/replay guarantees and resource limits. Windows remains excluded.
- Preserve failed attempts and measured limits. Do not substitute a green subset
  for a required local gate or infer historical causes from later passes.
- Reconcile local specifications, status and links; retire a local work record
  only after its library criteria and evidence are accounted for. Consumer
  acceptance can remain with its consumer without delaying local retirement.
